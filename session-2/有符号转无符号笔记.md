# 有符号转无符号：一张图看懂（CS:APP 第2章）

> 来源：Bryant and O'Hallaron, *Computer Systems: A Programmer's Perspective*, Third Edition（CS:APP 第3版）
> 课件：Conversion Visualized + Signed vs. Unsigned in C

## 0. 先记住一条根本事实

**内存里的一个数，是一串固定的 0 和 1。有符号和无符号，只是读这串东西的两种方法。** 转换 = 换一本字典读，位串一个都不改。

## 1. 转换图：两条轴，斜线连着

- 左边：**补码范围**，负的那头，从 -1、-2、-3……一路到 TMin（最负）。
- 右边：**无符号范围**，正的那头，最顶上 UMax（最大）。
- 中间的斜线：把左边每个负数，连到右边顶部。
- 规律：**-1 → 最大（UMax），-2 → 第二大，-3 → 第三大**……一个点一个点顺下来。

一句话：**负数转无符号，直接躺到最大数那一头去，读数顺序整个反过来。**

## 2. 具体例子（4 位）

- 内存里存 `1111`。
- 按有符号读：-1。
- 按无符号读：15。
- 值从 -1 变 15，**但位串从头到尾都是 `1111`**。

## 3. 绿色的部分（不用记，对照用）

- 非负数（0、TMax…）：转过去还是原数，不动。
- 只有**负数**才会跳到最大的那一头。

## 4. 这一堆图，在 C 里发生在哪

- **常量**：默认按有符号，想按无符号就加后缀 `U`。
  ```
  0U            // 无符号 0
  4294967259U   // 无符号大数
  ```
- **手动转换（casting）**：就是图上那张映射表。
  ```
  uy = (unsigned) ty;   // ty 是负数 → 变 4294967295
  ```
- **自动转换（隐式）**：赋值时编译器偷偷插进同一个转换，**不报错**。
  ```
  uy = ty;              // 等价于上面那行，悄悄转换
  ```

## 5. 现实坑：为什么它危险

- 例如 `if (i < n)`，i 是负数，n 是 unsigned。
- C 先把 i 转成无符号：-1 → 4294967295，是个**最大的数**。
- 于是"负数 i < n"原本该是真，转完变假，**比较结果错得离谱**，而且代码看不出毛病。

## 6. 一句话收尾

**负数转无符号 = 位串不改、读到最大数那一头去。C 里到处会自动触发这件事，且不提醒你——这就是有符号/无符号混用出 bug 的根源。**
