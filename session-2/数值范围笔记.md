# 数值范围 Numeric Ranges（大白话版）（CS:APP 第2章）

> 来源：Bryant and O'Hallaron, *Computer Systems: A Programmer's Perspective*, Third Edition（CS:APP 第3版）
> 课件：Numeric Ranges

## 0. 先建立一个场景：一排 16 个灯

- 电脑里存数，就是用 16 个"灯位"（bit），每个灯要么亮（1）要么灭（0）。
- 16 个灯亮灭的组合，一共 **65536 种**。所以这 16 个灯最多能表示 65536 个不同的东西。
- 问题来了：这 65536 种组合，每种"代表几"？有**两套规则**可以选。

## 1. 规则 A：无符号（假装世界上没有负数）

- 把灯的排列**从 000...0 数到 111...1**，当成 0、1、2、3……一路数上去。
- 最小：全灭 = 0；最大：全亮 = **65535**。
- 大白话：**把所有组合都当成非负整数，0 到 65535**。

## 2. 规则 B：补码（一半分给负数）

- 把灯位里的**最左边那一位当成"正负号"**：亮=负，灭=正。
- 所以范围变成：**从 -32768 到 +32767**，一共还是 65536 个数（负数多占了一个，正数少一个）。

## 3. 同一排灯，两套读法，结果差一倍

- 比如 16 个灯**全亮**（`1111...1`）：
  - 用规则 A 读 → **65535**。
  - 用规则 B 读 → **-1**。
- 灯没变，全亮就是全亮；**差的是你决定"按哪套规则解读它"**。电脑只存灯亮灭，它不知道自己存的是 65535 还是 -1，这是你写代码时选的关键字（`unsigned` 还是 `int`）决定的。

## 4. 关键记忆点就一个

> **16 个灯只有 65536 种排列。配"无符号" = 0~65535；配"补码" = -32768~32767。同一个全亮的灯串，口中可以喊 65535，也可以喊 -1。**

## 5. 对照 PPT 底部表格（w=16）

| 名字 | 十进制 | 就是这一排灯 |
|:---|:---:|:---|
| UMax（无符号最大） | 65535 | `1111...1` |
| TMax（补码最大正数） | 32767 | `0111...1` |
| TMin（补码最小负数） | -32768 | `1000...0` |
| -1 | -1 | `1111...1` ← 和 UMax 同一排灯！ |
| 0 | 0 | `0000...0` |

## 6. 一句话大白话

**这一页在说：同一串 0 和 1，按"无符号"读是一种范围，按"补码"读是另一种范围；灯不变，变的是一套解读方式。**
