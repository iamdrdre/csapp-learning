# 深入理解计算机系统之"信息表示"（CS:APP 第2章进阶）

> 这 10 篇笔记不是零散知识点，它们沿着课程的主线层层递进。这篇按主线脉络重写，去掉比喻，把每一层的因果讲清楚。

## 0. 主线

**计算机里的信息，是一条从"位"到"语言行为"的因果链：位编码 → 位操作 → 数值解读 → 类型转换。每一层建立在前一层之上，后一层出现的一切"意外"，都能回溯到前一层。**

## 1. 第 1 层：位编码

**结论：一切信息最终都是 0 和 1 的序列。**

- 因为计算机只有"有电/没电"两种状态，所以所有信息（数字、字符、程序）都编码成 0/1。
- 1 字节 = 8 位，是基本单位；16 个 0/1 用十六进制写只需 4 个字符，所以十六进制是二进制的缩写，`0x` 是 C 里的记号。
- 整数转二进制精确；小数（如 1.2）转二进制无限循环，存不下就舍入——**浮点数从此天生带误差**。
- 机器字长 = 地址宽度：32 位地址 = 4 字节，64 位地址 = 8 字节。可寻址空间 = 2^字长，所以字长直接锁定内存上限（32 位 ≈ 4GB）。

## 2. 第 2 层：位操作

**结论：位上的运算，规则来自布尔代数；每种运算都服务一个具体目的。**

- 与、或、非、异或：规则由真值表定义，对一个 w 位的数逐位应用，每一位独立。
- 位向量的意义：一位对应集合里的一个元素，1 = 在集合里，0 = 不在。于是集合的交、并、补 = 位运算，一条指令完成。
- 逻辑运算（&&、||、!）和位运算不同：只看整个数是否为 0（非 0 即真），结果只有 0 或 1，且短路（左边能定结果，右边不执行）。
- 移位：左移低位补 0；右移分逻辑（补 0）和算术（补符号位）两种——因为负数右移必须保住符号。移位次数 ≥ 位数是未定义行为，必须避开。

## 3. 第 3 层：数值解读

**结论：同一串位本身不含"是几"的信息；数值由解读规则决定。**

- 规则一（无符号）：所有位当正数，范围 0 ~ 2^w−1。
- 规则二（补码）：最左位当符号（是 1 为负），范围 −2^(w−1) ~ 2^(w−1)−1。
- 补码选择"最高位 1 = 负数"的原因：使加法和减法共用一套电路，正负计算不区分；代价是正数区比负数区少一个数。
- 非负数（最左位为 0）在两种规则下读出的值相同；只有最左位为 1 时才分道扬镳。
- 位串与数值一一对应（每个位串只有一个无符号值、一个补码值），所以可以双向查表转换。

## 4. 第 4 层：类型转换

**结论：转换只改变解读规则，不改变位本身；由此产生三类可预见的"意外"。**

- 有符号 ↔ 无符号：位串原样保留，换一套读法。负数转无符号 = 数值加 2^w，跳到最大正数区（-1 → 4294967295）。C 语言中常量加 U 后缀、显式强转、隐式赋值都会触发，隐式的不报错。
- 混合类型比较：表达式里有无符号，有符号自动转无符号，负数变巨大正数，比较结果反转（-1 > 0U 为真）。这是 signed/unsigned 混用 bug 的根源。
- 扩展（小 → 大）：无符号补 0，有符号复制符号位（符号扩展），数值必定不变。
- 截断（大 → 小）：丢弃高位，等价于对 2^k 取模（无符号）；有符号类似取模但可能变负数。只有原本放得下的数才安全。

## 5. 收束：这条主线给了你什么

- 遇到"数字不对"的程序，检查顺序固定：位是否被截断/环绕 → 解读规则是否被隐式替换 → 类型是否混用。三个检查点全在这条链上。
- 后面学内存、汇编、虚拟内存时，"位 + 解读"这条链是底层共识：无论上层多复杂，最终都是按层回溯到位编码。
