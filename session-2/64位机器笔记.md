# 64 位机器与地址（CS:APP 第2章）

> 来源：Bryant and O'Hallaron, *Computer Systems: A Programmer's Perspective*, Third Edition（CS:APP 第3版）
> 课件：Example Data Representations（C 数据类型大小表）+ 课堂讲解

## 0. 背景：一张表格（Example Data Representations）

| C 数据类型 | 典型 32 位 | 典型 64 位 | x86-64 |
|:---|:---:|:---:|:---:|
| int | 4 | 4 | 4 |
| long | 4 | 8 | 8 |
| double | 8 | 8 | 8 |
| pointer（指针） | **4** | **8** | **8** |

**关键观察**：指针（存的是一串地址）在 64 位系统下从 4 字节变 8 字节——地址的长度跟着机器走。

## 1. 第一条：虚拟地址空间由机器字长决定

- **规则**：地址的长度 = 机器字长（word size，机器一次能处理的位数）。
  - 32 位机 → 地址 32 位（4 字节）
  - 64 位机 → 地址 64 位（8 字节）
- **推导**：地址是个数，能表示多少个地址取决于位数：
  - 32 位地址 → 最多 2³² 个 → 可寻址上限 **4GB**
  - 64 位地址 → 最多 2⁶⁴ 个 → 基本"想装多少装多少"
- **结论**：字长 → 地址长度 → 可寻址空间，这一串是连着的。

## 2. 第二条："64 位机器"的真正含义

- 原话：*"当他们说这是一台 64 位机器时，真正含义是地址是 64 位值（8 字节）。"*
- **关系**：第一条讲"规则"，这一条讲"翻译"——把市场术语翻译成技术事实。
- 连起来：**"64 位机器" = 字长 64 位 = 地址 64 位 = 8 字节**（64 ÷ 8 = 8）。
- **为什么教授要澄清**：因为"64 位机器"容易被误解成"CPU 一次算 64 位"，真正被定义死的是**地址的宽度**。

## 3. 第三条：这句话的实际意义

**定义层面**
- "64 位机器"指的就是：硬件发的每个地址号是 64 位的（8 字节）。

**后果层面（内存上限）**
- 64 位地址最多 2⁶⁴ 个 → 理论上限 ≈ 2⁶⁴ 字节 ≈ 1600 万 TB，内存几乎不受限。
- 对比：32 位上限 2³² = 4GB——**这就是当年 32 位电脑内存卡在 4GB 的原因**。

**程序员视角（指针变胖）**
- 指针从 4 字节变 8 字节 → **64 位程序里每个指针多占一倍内存**。
- 链表、树这类全是指针的数据结构，在 64 位下明显更费内存。
- 32 位程序不能直接跑在 64 位环境（需要兼容层），根源也是地址宽度对不上。

## 4. 一句话核心

**"64 位机器" = 地址 8 字节 = 内存上限不再是 4GB = 指针变胖了一倍。** 机器字长锁死了地址长度，地址长度锁死了可寻址的内存空间。
