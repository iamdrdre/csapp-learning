# Casting Surprises：混合类型比较的意外（CS:APP 第2章）

> 来源：Bryant and O'Hallaron, *Computer Systems: A Programmer's Perspective*, Third Edition

## 0. 一条核心规则（背下来）

**一个式子里只要有符号和无符号混在一起，有符号的会被偷偷转成无符号，再继续算。比较运算（`<`、`>`、`==`）也逃不掉。**

32 位字长下，先记两个边界数：

- TMAX = 2,147,483,647（最大的有符号正数）
- TMIN = -2,147,483,648（最小的有符号负数）

## 1. 9 个例子，一行一行看

| 式子 | 咋回事 | 结果 |
|:---|:---|:---|
| `0 == 0U` | 两个都是 0 | 真 |
| `-1 < 0` | 全有符号，正常 | 真 |
| `-1 > 0U` | -1 转无符号 → 4,294,967,295（最大数） | **真**（本该是假） |
| `2147483647 > -2147483647-1` | 全有符号，正常 | 真 |
| `2147483647U < -2147483647-1` | TMIN 转无符号 → 2,147,483,648（比 TMAX 大） | **真**（本该是假） |
| `-1 > -2` | 全有符号，正常 | 真 |
| `(unsigned)-1 > -2` | -1 = 4,294,967,295；-2 也自动转 = 4,294,967,294 | 真 |
| `2147483647 < 2147483648U` | 左边转无符号，2147483647 < 2147483648 | 真 |
| `2147483647 > (int)2147483648U` | 2147483648U 强转有符号 → 溢出成 TMIN（负数） | 真 |

## 2. 规律

- 全有符号：正常，该真就真。
- 混进无符号：**负数瞬间变成大正数**，原来该假的变成真。
- 手动强转 `(int)`：把大无符号数塞回有符号，**溢出变成负数**。`(int)2147483648U` 不是 2147483648，而是 -2147483648。

## 3. 一句收尾

**混合比较时，有符号的负数会被自动当成巨大正数，`-1 > 0U` 竟然为真——这就是"意外"，也是别在有符号和无符号之间做比较的原因。**
