# 有符号与无符号的转换（大白话版）（CS:APP 第2章）

> 来源：Bryant and O'Hallaron, *Computer Systems: A Programmer's Perspective*, Third Edition（CS:APP 第3版）
> 课件：Mapping Between Signed & Unsigned

## 1. 核心事实

**内存里的一个数，本质就是一串固定的 0 和 1。"有符号"（补码）和"无符号"只是读这串 0 和 1 的两种方法。转换就是换一种读法，0 和 1 一个都不变。**

## 2. 具体规则（4 位为例）

1. 内存里存的是 `1111` 这一串。
2. 按**无符号**读：每一位是 2 的次方（8+4+2+1）= **15**。
3. 按**补码**读：最左边一位算负数（-8+4+2+1）= **-1**。
4. 所以同一个 `1111`，可以叫 15，也可以叫 -1。区别只在"你决定用哪种读法"，数字本身没有改变。

## 3. 转换流程（去掉符号看实质）

- 补码数 -1 → 取出它的位串 `1111` → 用无符号方法读 → 得到 15。
- 无符号数 15 → 取出它的位串 `1111` → 用补码方法读 → 得到 -1。
- 两步之间位串都是 `1111`，**没有发生任何变化**，变的只是最后那一下"读"。

## 4. 和 C 语言的关系（为什么这页重要）

- C 里写 `(unsigned)x` 就是把 x 的位串拿出来，用无符号方法读一遍。位串原封不动。
- 例子：32 位机器上，`(unsigned)(-1)` = 4294967295。原因：-1 的位串是 32 个 1，按无符号读就是 2³²−1 = 4294967295。
- 这就是为什么有符号数转无符号数经常得到"特别大的正数"——**位串没变，只是读数方法变了**。

## 5. 结论

**有符号和无符号的互相转换，只是对同一串 0 和 1 换一种解读方式，数据本身不经过任何算术修改。**
