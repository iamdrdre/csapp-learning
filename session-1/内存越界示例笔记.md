# 内存引用错误示例（Memory Referencing Bug）

> 来源：Bryant and O'Hallaron, *Computer Systems: A Programmer's Perspective*, Third Edition（CS:APP 第3版）

## 1. 示例代码

```c
typedef struct {
    int a[2];        // 数组：2 个 int
    double d;        // double，8 字节
} struct_t;

double fun(int i) {
    volatile struct_t s;   // volatile 防止编译器优化掉读写
    s.d = 3.14;            // 先把 d 设为 3.14
    s.a[i] = 1073741824;   /* 1073741824 = 2^30 = 0x40000000
                              注意：i 可能越界（合法索引只有 0、1） */
    return s.d;            // 返回 d
}
```

## 2. 内存布局（大白话）

结构体 `s` 在内存里按顺序排：

```
[ a[0] ] [ a[1] ] [      d (8字节)     ]
   4字节     4字节           8字节
```

- 前面两个小格放 `a[0]`、`a[1]`
- 后面一个大格放 `d`，里面存 3.14

## 3. 代码在干什么

1. 先在大格 `d` 里放 3.14
2. 再往第 `i` 个位置塞一个很大的数（2³⁰）
3. 最后看 `d` 现在是几

**问题**：前面只有两个空位，但代码一直往第 3、4、5…个位置塞。第 3、4 个位置根本没有抽屉——那里其实是大格 `d` 的地盘。于是大数把 3.14 直接改坏了。

## 4. 运行结果

| 调用 | 返回值 | 咋回事 |
|:---|:---|:---|
| fun(0) | 3.14 | 正常，写在自己的地盘 |
| fun(1) | 3.14 | 正常 |
| fun(2) | 3.1399998664856 | 盖掉了 d 的低位，值略变 |
| fun(3) | 2.00000061035156 | 盖掉了 d 的高位，3.14 变 2.0 |
| fun(4) | 3.14 | 写到结构体外但没撞坏 d |
| **fun(6)** | **程序崩溃** | 越界太远，撞到系统保护的内存 |

## 5. 一句话核心

**C 语言不检查下标是否合法**。写越界会静默破坏相邻数据（这里是 `d`），这就是内存 bug。

字幕那句"直到调用 fun(6) 程序才崩溃"的意思：

> 前面几次越界都没事、不吭声，但**不代表没事**。越界一直在发生，只是运气好没崩，运气用完（fun(6)）才崩。

## 6. 教训

- 越界写不是第一次就越界，而是早就越界、只是没暴露
- 不报错 ≠ 没出错，C 里越界是"未定义行为"
- 这正是缓冲区溢出漏洞的根源（后续章节会讲攻击利用）
